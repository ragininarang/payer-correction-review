## Judge testing instructions to ship with the app

1. Use an eligible Atlassian Cloud test site with Jira/JSM, admin installation rights and an internal service project. Document enabled Rovo capabilities and optional Confluence installation. Record exact tested plans, scopes and configuration steps before publishing. The developer's backend OpenAI key funds judged synthetic runs; do not ask judges for an API key. Link to the verified production distribution URL. [Distribution guide](https://developer.atlassian.com/platform/forge/distribute-your-apps/#start-sharing-your-app)
2. In the app, choose **Initialize synthetic example**, then open its internal JSM case. Display a clear synthetic-data banner and the seeded source versions. Seeding again should open the same scenario or explicitly create a separate copy.
3. Confirm the source-backed rule for 12 eligible lines. Inspect the missing correction, supply the final adjustment and approve revision 2. If actor roles require switching users, include a tested admin role-mapping procedure.
4. Reimport the same batch, then introduce the late reversal of line 07. The first action leaves the result unchanged. The second reopens the case and shows $100 unresolved with a source reference. Change inventory coverage to unconfirmed to exercise a different closure outcome.
5. Ask Rovo why the case reopened. For the MCP track, provide tested steps to connect a second Rovo Studio agent and call the revision-difference tool. Supply the expected structured response plus setup, denial, and troubleshooting guidance. The install guide should also explain how to recover a stalled run and remove the synthetic case.
